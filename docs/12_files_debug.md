# 文件、调试与工程习惯

对应S1第9单元、S6各实验选作与综合应用。练习21和实验文件流水线。

## 文件操作顺序

打开→检查指针→按成功读取次数循环→检查错误→关闭。`FILE *`是库管理的流，不是磁盘内容的普通内存地址。

|模式|行为|
|---|---|
|r|读已有文件，不存在失败|
|w|写，存在则截断，不存在则创建|
|a|追加，写入到末尾|
|r+|已有文件读写|
|w+|截断后读写|
|rb/wb|二进制读/写（某些平台与文本模式有差别）|

```c
FILE *fp=fopen("scores.txt","r");
if(!fp) return 1;
int x;
while(fscanf(fp,"%d",&x)==1) { /* 处理刚刚成功读出的x */ }
if(ferror(fp)) { /* 读错误 */ }
fclose(fp);
```

不要用`while(!feof(fp))`：EOF标记通常在读失败后才设置，容易重复处理最后一个值。`fgetc`返回int，要保留EOF；`fgets`一行可能被截为多次读取。fscanf返回0意味着格式不匹配，也要处理，不能让循环卡在同一个坏字符。

`fread(ptr,size,count,fp)`返回成功读取的**元素个数**；fwrite同理。`fseek/ftell/rewind`管理位置；二进制流适合字节偏移。文本模式随意用固定字节偏移不普遍可移植。`%5d`只是最小宽度，若数值超过宽度或混入换行，就不能假设每条记录恰5字节；S1文件定位题必须先满足固定记录格式前提。

更新流在写后转读、读后转写时有定位/刷新要求；21使用fflush再fseek。多个文件打开若其中一个失败，关闭已经成功打开的文件。

直接把struct写成二进制存在布局、字节序、浮点表示与填充差异；本机课堂练习可在同实现下读回，不能当跨平台文件协议。含指针/string/vector的对象绝不能按原始内存当持久化记录。更稳妥的交换格式是逐字段文本，或明确定义宽度与字节序的二进制格式。

## 断点调试的五个动作

1. 用`-g -O0`构建；在main或可疑循环前打断点。
2. 单步跳过（next）观察状态；单步进入（step）观察函数形参。
3. 打印变量、数组片段、指针及其指向对象。
4. 条件断点定位某个下标或第几轮，不靠铺满printf。
5. 崩溃时看调用栈（backtrace），从第一次错误数据出现处修。

```bash
gcc -std=c99 -g -O0 src/c/17_pointers.c -o pointers
gdb ./pointers
# break main / run / next / print x / print *p / backtrace
```

编译错误是语法/类型等问题；链接错误常见于缺实现、重复main、忘记-lm；运行错误有越界、未初始化、除零等；逻辑错误即使程序正常退出也会输出错结果。严格警告、ASan/UBSan、边界样例分别抓不同问题；测试通过不等于证明任意输入都正确。

## 考场改错清单

- 头文件、返回类型、声明与定义一致吗？
- scanf的格式和地址匹配吗？printf有没有少参数或误传地址？
- 判断写成赋值了吗？for三个表达式是否用分号？
- 累加/乘积/极值初值是否正确？
- 数组下标从0到n-1吗？字符数组容量是否包括零字符？
- 是否漏break、循环更新、递归基、return？
- malloc是否检查，文件是否检查，资源是否释放？

C++11的fstream示例：`std::ifstream in("scores.txt"); std::ofstream out("result.txt");`先检查流状态，使用`while(in>>x)`控制读取；析构自动关闭，但需要确认落盘错误时可显式flush并检查状态。
